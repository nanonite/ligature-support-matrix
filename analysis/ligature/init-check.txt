================================================================
### DECISIONS, AND WHY
================================================================

1. `closure_kind: "deductive"` (top level, schema enum
   ['deductive','bounded','partial']). This is the intent the plan's P2
   heading states and the pilot README already carried
   (`Intended closure_kind: deductive`). It is set here, before any Rust
   exists, which is the whole point of the field: probe P1 confirms the
   enum is enforced with a property-level diagnostic, and the schema's
   own description says gate g14 later recomputes closure_kind from the
   evidence actually present, so this is a declaration of intent, not a
   claim. P1 needed a side record for this; that is obsolete
   (epic #1 #72).

2. `verifier_policy: {"default": "verus"}` and nothing else.
   `verifier_policy` deliberately has no `supporting: ["kani"]` yet:
   whether the unsafe/raw-pointer slots and the SIMD group-probing half
   become a Kani-owned sub-cluster or a `Vec<Option<T>>` scope cut is
   exactly what chainlink #35 and #36 have to decide, and declaring a
   supporting verifier now would fix that answer before the probes that
   decide it have run. The `status --json` read-back confirms the
   effective policy is exactly {clusters: {}, default: verus,
   supporting: []}.

3. `crates[0].contracts_crate: "verus_contracts"` rather than the init
   template's `contracts`. The field is "the verifier-contracts facade
   crate this crate's generated stubs depend on"; for a Verus pilot that
   facade is `verus_contracts` (the vstd library), not Creusot's
   `contracts`. This is a Verus-specific intent fixed before code
   exists, which is what this issue is for. Revisit when #30 creates the
   crate, if the actual facade name differs.

4. `write_set.protected_roots` uses crate-scoped globs
   `rust/*/Cargo.toml` and `rust/*/build.rs`, NOT the init template's
   `**/Cargo.toml` / `**/build.rs`. The `**` forms overlap the allowed
   roots `rust/*/src/`, which is the P1 G13 failure recorded as #105 /
   date-ligature-034. Probe P7 below confirms the `**` form is
   schema-valid and write-set-clean at P0, so nothing at this stage
   would have caught it -- it is Stage 7 that rejects it.

5. `write_set.allowed_roots` was widened from the template's
   `crates/*/src/` + `crates/*/tests/` to this pilot's real footprint
   (`rust/*/...`, `analysis/**`, `findings/**`, `oracle/**`, `tools/**`,
   `upstream/**`, `specs/_closure/**`, `specs/_promotions/**`,
   `README.md`, `.envrc`, `.mcp.json`, `rust/.gitkeep`). Left as the
   template shipped, write-set-check reported the whole pinned upstream
   checkout plus every pilot-owned directory as out-of-set writes
   (exit 1). Widening is the intended behaviour, not a defect.
   `crates/` was dropped rather than kept, because this pilot's Rust
   workspace is `rust/` (WORKER-CONTRACT.md section 4 and the plan's
   directory map), so `crates/*/...` would have described a directory
   that does not and will not exist.

6. `port_source.oracle_build_command` is the abseil-cpp configure+build
   invocation, and it was re-run in this session (exit 0, "ninja: no
   work to do" over #25's existing build tree). It builds and tests the
   C++ side the differential oracle will link against. The oracle driver
   itself does not exist yet -- that is #32 -- and the descriptor's own
   field description is "Command that builds/runs the origin-language
   oracle", so #32 should tighten this field to the driver's own build
   once there is one. Recording a command that cannot run would be
   worse than recording the verified one.

7. `port_source` has no `commit`. `port_source` is
   `additionalProperties: false` with only repository / language /
   oracle_build_command, so the pinned commit
   `2065f4ded0558c6f89fee67c8e5228feb4eb960e` stays in
   `upstream/upstream-pin.json` and `README.md`, as in P1
   (epic #1 #72).

8. `gate_integrity` is the init template's four entries, unchanged.
   `validate-work-package`'s own help text says G13 additionally requires
   `scripts/witness_renderer.py` and `scripts/xml_escape.py` to each have
   a `gate_integrity` entry, protected coverage and no allowed coverage.
   Both scripts were installed by `init` and are already protected by
   `scripts/**`, but adding their gate_integrity entries is Stage 7's
   job (#29), and `ci/manifest/installation.json` pins `gate_hashes` for
   exactly the four entries the template declares. Widening the pin list
   is not this issue's call to make.

9. `review.reviewer` is `chainlink-reviewer` / `2026-10-02`, replacing
   the template's `example-reviewer` / `2026-08-25` placeholder. It
   records the workspace's own review convention (as in P1). A ruling
   under `record-ruling` remains a human action and is not implied here.
