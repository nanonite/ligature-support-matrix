3. NEW: the exact grammar G9 accepts
-------------------------------------
Probed by rewriting `bridge_logic.premises` in place on the scratch and re-running
`check-bridges` for each candidate. ACCEPTED:

    ["self"]                        bare declared binding
    ["slot"]                        bare declared binding
    ["self.ctrl.len()"]             dotted chain
    ["self.foo()"]                  chain ending in a call
    ["self.a.b.c"]                  deeper dotted chain
    ["self.foo(slot)"]              call argument is a declared binding
    [""]                            the empty string (so "at least one premise"
                                    is not enforced by G9)

REJECTED, each with its own message:

    ["x == y"]        unexpected character '=' at offset 2
    ["x < 16"]        unexpected character '<' at offset 2
    ["x && y"]        unexpected character '&' at offset 2
    ["x + y"]         unexpected character '+'
    ["forall|i: u64| true"]
                      unexpected character '|' at offset 6
    ["self.ctrl[0]"]  unexpected character '[' at offset 9
    ["self.f(0xFF)"]  unexpected character '0' at offset 7   (literal argument)
    ["Self::f()"]     unexpected character ':' at offset 4   (no paths)
    ["foo(self)"]     premise[0]: foo is rooted at 'foo', which bridge_logic.bindings
                      does not declare (declared: ['h', 'i', 'mirror_index_wraps_
                      inside_the_array', 'self']) -- a harness cannot pass a value it
                      was never given

The declared set is `bridge_logic.bindings` keys PLUS every
`required_local_facts[].fact_id`. A binding key that is not snake_case is rejected
separately: `binding name 'GROUP_WIDTH' is not snake_case -- it becomes a harness
parameter name`.


4. NEW: check-bridges is not read-only, and --workspace is a global flag
------------------------------------------------------------------------
`check-bridges` writes a generated harness into the workspace:

    $ cat ci/harness/BR-CONTROLBYTES-SETDEAD-001.verus.rs
    // GENERATED by scripts/bridge_harness.py -- do not edit.
    // bridge_id: BR-CONTROLBYTES-SETDEAD-001
    // boundary_id: raw_table_erase__to__control_bytes_set_dead
    // verifier: verus
    // conclusion: ControlBytes.C003
    // plan.md §8.2: caller preconditions ∧ invariants ∧ path condition ∧ prior call
    // results ⟹ callee precondition. The premises below are the assumed facts; the
    // conclusion is what the owning verifier must establish from them.
    verus! {
        proof fn bridge_br_controlbytes_setdead_001(self: RawTable, slot: usize)
            requires
            self.is_full_ctrl(slot),
            self.is_not_sentinel_ctrl(slot),
            ensures
            ControlBytes::C003(self, slot),
        {
        }
    }

Note what this shows: each premise is pasted verbatim into a Verus `requires`
clause, so a premise must be a boolean-valued term for the harness to compile. A
premise written the way the template describes it (`slot < self.capacity()`) is a
valid boolean and is rejected; one written as a term (`self.ctrl(slot)`) is accepted
and is not a boolean. The only shape that satisfies G9 is a call to a
boolean-returning predicate over the bindings -- which means the predicate has to
actually exist as a method on the ported type.

`write-set-check` stays clean with that generated directory present:

    $ python3 tools/ligature/ligature.pyz write-set-check ; echo $?
    write set: clean
    ...exit 0

because `ci/harness/**` is in neither `allowed_roots` nor `protected_roots` of
`project-descriptor.json`. Same class as WORKER-CONTRACT §0.0's `ci/manifest/`
observation, one directory over.

`--workspace` is a GLOBAL flag and must precede the subcommand:

    $ python3 tools/ligature/ligature.pyz check-bridges --workspace /abs ; echo $?
    2                       # argparse usage error
    $ python3 tools/ligature/ligature.pyz --workspace /abs check-bridges ; echo $?
    1                       # the real G9 findings

(1.2.1 has the relative-`--workspace` fix from #96, so the absolute form is no
longer needed for correctness here; it is recorded because WORKER-CONTRACT §0.0
says "pass an absolute `--workspace`" without saying where in the command line it
goes, and putting it in the wrong place exits 2 rather than working.)


5. One measurement trap worth recording for the next worker
-----------------------------------------------------------
This loop prints a WRONG exit code, and it is easy to believe:

    for f in .../*.json.draft; do
      python3 tools/ligature/ligature.pyz approve "${f%.draft}" --reviewer X >/dev/null 2>&1
      echo "$(basename "${f%.draft}") approve exit=$?"
    done

`$(basename ...)` is a command substitution inside the same word as `$?`; bash
expands left to right, so the substitution runs first and sets `$?` to basename's
status. Every line reads `exit=0` regardless of what `approve` did. Capture the
status into a variable before echoing anything else:

    out=$(python3 tools/ligature/ligature.pyz approve "$t" --reviewer X 2>&1); rc=$?

This cost one wrong conclusion in this pass before it was caught: it made six
failing `approve` calls look like six successes.
